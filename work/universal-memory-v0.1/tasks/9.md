# Task 9: Tag every row with its embedding model; never compare across models silently

## Description

The cheap half of `work/embedding-bridge/`, pulled forward because v0.1 creates the
exact hazard it guards against. Task 2 permits substituting a smaller embedding model
if the first choice does not fit the host. Do that after task 4 has ingested the corpus
and every existing memory silently becomes unfindable — vectors from two different
models are not comparable, and nothing in the code notices.

The failure is worst when the dimensions happen to match. `config.ts` selects
`google:text-embedding-004` (768) or `ollama:nomic-embed-text` (768) depending on which
key is present; those two spaces are geometrically unrelated, so cosine computes, results
come back, and they are noise. A loud dimension-mismatch error is survivable. This is not.

This task is the guard only. The bridge that actually makes cross-model search work —
anchor-relative projection — stays in `work/embedding-bridge/`, gated behind its own
evaluation and behind the v0.1 verdict.

## What to do

- Record the resolved embedding model identifier on every stored memory. `config.ts`
  resolves it already but only logs it — export it and persist it alongside the row.
- On search, compare only within one embedding model. Rows written under a different
  model are excluded from vector scoring rather than scored badly.
- When the active model differs from the model rows were written under, say so: a clear
  startup or query-time warning naming both identifiers and the count of unreachable
  rows. Silence is the defect being fixed.
- Handle rows written before this task, which carry no identifier: treat unknown as
  not-comparable rather than assuming they match the current model.
- Document the operational rule in `README.md` next to the embedding configuration:
  changing the embedding model on an existing database strands every memory until the
  bridge ships or the corpus is re-ingested.

## TDD Anchor

- `rows_carry_embed_model_identifier` — a captured memory stores the resolved model id.
- `search_excludes_rows_from_a_different_model` — seed rows under model A, search under
  model B, assert those rows are not returned by the vector path rather than returned
  with poor scores.
- `same_dimension_different_model_is_still_excluded` — the 768/768 case, which is the
  one that fails silently today.
- `model_change_is_reported` — switching models produces a warning naming both ids and
  the count of stranded rows.
- `legacy_rows_without_identifier_are_not_assumed_current`.

## Acceptance Criteria

- [ ] Rows with no identifier are treated as not comparable
- [ ] The operational rule is documented next to the embedding configuration
