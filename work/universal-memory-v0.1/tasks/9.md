# Task 9: Release — deploy, documentation actualisation, tag

## Description

Everything before this proves a piece. This task ships: one live instance, documentation
that matches the code, and a tag. `DEPLOY.md`, `docker-compose.yml`,
`docker/memory-hub/Dockerfile` and `nginx/memory.conf` all exist and have never been
exercised against a real host.

## What to do

- Deploy one instance following `DEPLOY.md` exactly, and fix the document wherever it
  turns out to be wrong — an unfollowed runbook is a draft, not a runbook.
- Verify from outside: an HTTP Model Context Protocol call over HTTPS with a Bearer
  token, capture and recall against the deployed instance, and the health endpoint the
  Dockerfile's healthcheck probes.
- Confirm the deployment refuses unauthenticated requests. Check what the server logs
  on failure — the config module scrubs secrets, and that scrubbing must hold in
  production, not only in tests.
- Actualise the documentation against what now exists:
  - `README.md` roadmap — six unchecked boxes, four of them substantially built;
  - the tool table — `memory_sync` is registered but only pushes (pull returns 0);
  - `docs/architecture.md` — it designs ConversationIngestor, ResearchIngestor and
    VoiceIngestor, none of which exist. Mark them as designed-not-built rather than
    deleting the design.
- Write the v0.2 backlog into `work/` from the deferred list in the user spec, so it
  survives this release rather than living in a chat.
- Tag `v0.1.0` and note in `decisions.md` what shipped and what did not.

## TDD Anchor

Not applicable — this is a release gate. Its verification is external observation of a
running system.
