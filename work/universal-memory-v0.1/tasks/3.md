# Task 3: Zero-install client connection from any machine

## Description

Today "installing" the client means cloning the repository, initialising submodules and
running two `bun install`s. On a locked-down work machine that is impossible: no
administrator rights, no package manager, often no compiler, and outbound traffic only
through a corporate proxy that terminates TLS with its own certificate authority. The
hosted instance from task 1 already speaks HTTP with Bearer authentication, so the
client needs nothing but a URL and a token.

## What to do

- Write the connection recipe for the Model Context Protocol clients we actually use —
  Claude Code and Cursor — as a configuration block with the hosted URL and the token.
  No clone, no build, no elevated rights.
- Verify it from a machine that has never seen this repository. Simulate the locked-down
  case honestly: unprivileged user, no repository present, egress only through an HTTPS
  proxy with a custom certificate authority bundle.
- Document token handling: where it is stored per client, how it is rotated, and what to
  do when it leaks. The token grants full write access to the brain — say so.
- Document the offline fallback in one paragraph: local mode exists for a disconnected
  machine, and memories written there do not travel, because `HybridAdapter` implements
  push only. Do not imply sync that does not exist.
- Record which parts were verified against a real restricted environment and which
  against a simulated one (risk R3).

## TDD Anchor

Not unit-testable. Verification is a connection from a clean machine.

## Acceptance Criteria

- [ ] A documented configuration block connects Claude Code to the hosted instance

- [ ] The offline fallback is described without implying two-way sync
- [ ] What was simulated rather than tested in a real perimeter is stated
