# Task 3: RUMBA dataset availability

## Description

`research/RUMBA` is recorded in the tree as a gitlink (`160000 commit ba08160…`) but
has no entry in `.gitmodules`. `git submodule status` fails outright with "no submodule
mapping found in .gitmodules for path 'research/RUMBA'", and the directory is empty on
every clone. `packages/eval/run.py` expects
`research/RUMBA/evaluation/data/data_locomo_format_en.json` and therefore cannot run at
all. This task makes the dataset reachable; task 4 uses it.

## What to do

- Establish where `ba08160` came from and whether that upstream is still reachable.
  RUMBA is described in `README.md` as a benchmark covering memOS, mem0, Graphiti,
  Cortex and retrieval-augmented generation baselines.
- Then either: (a) add the correct `[submodule "research/RUMBA"]` mapping to
  `.gitmodules` and re-pin to a commit that exists, or (b) if the upstream is gone or
  unsuitable to pin, vendor only the evaluation dataset under `research/RUMBA/` as
  ordinary tracked files, recording licence and provenance in a `SOURCE.md` beside it.
- Whichever path is taken, record the choice and its reason in `decisions.md`.
- Update `README.md`'s clone instructions if the submodule set changes.
- Confirm `packages/eval/run.py --dry-run` reaches the dataset. Install its `jinja2`
  requirement if needed and note it in the eval documentation.

## TDD Anchor

- `git submodule status` completes without error on a fresh clone.
- `python run.py --service universal-memory --backend local --dry-run` exits 0 and
  reports the dataset path it loaded and the number of conversations found.

## Acceptance Criteria

- [ ] `git submodule status` no longer errors on `research/RUMBA`

- [ ] `run.py --dry-run` exits 0
