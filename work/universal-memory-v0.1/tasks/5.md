# Task 5: Embedding path (hybridSearch) test coverage

## Description

Semantic search is the product's core retrieval feature and no test executes it. Every
suite run so far has been BM25-only, because no embeddings key is present in the test
environment: `embeddingsEnabled` resolves false, `add()` stores with `noEmbed`, and
`search()` takes `engine.searchKeyword` instead of `hybridSearch`. The vector arm plus
Reciprocal Rank Fusion — the part that makes this more than keyword search — is
entirely unexercised.

## What to do

- Add an integration suite that runs `LocalAdapter` with a real embeddings provider
  configured, asserting `hybridSearch` is the path taken.
- The load-bearing assertion is semantic, not lexical: store a document and retrieve it
  with a query that shares **no** significant terms with it, which BM25 alone cannot
  satisfy. That single test is the whole point of the task.
- Provider choice: prefer a local Ollama with `nomic-embed-text` so the test needs no
  paid key and can run in continuous integration; fall back to `OPENAI_API_KEY` gated
  by its presence. Anthropic cannot serve this — it has no embeddings interface (see
  `docs/HANDOFF-adapter-integration.md`).
- Per decision D3, when no provider is configured the suite must print an explicit
  skip line naming the missing variable. It must never silently pass in BM25 mode.
- Wire the provider into the continuous integration workflow from task 1 if it can run
  there; otherwise document the local command and make the skip visible in the log.

## TDD Anchor

- `hybrid_search_finds_semantically_related_document` — store "The feline rested on the
  woven floor covering", query "cat sleeping on a rug", assert a hit. Must fail when
  forced down the keyword path.
- `embeddings_disabled_skips_loudly` — with no provider variables set, the suite emits
  a skip naming them and does not report a pass.
- `capture_stores_embeddings_when_provider_present` — assert stored chunks carry
  vectors, not only text.

## Acceptance Criteria

- [ ] A test exercises `hybridSearch` against a real embeddings provider
- [ ] A no-shared-terms semantic query retrieves the right document
- [ ] That test fails if forced onto `searchKeyword` (verify by temporarily forcing it)
- [ ] Absence of a provider produces a visible skip, never a silent pass
- [ ] `bun run test` stays green in both configurations
- [ ] The chosen provider and how to run it locally are documented
