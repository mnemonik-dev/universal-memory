# Task 5: Daily-use loop wired into the agent

## Description

A memory that has to be remembered will not be used. The agent must reach for it on its
own: search before starting work, capture after deciding something. The pattern already
exists for one consumer — `adapters/fabric/CLAUDE.md` instructs Fabric agents exactly
this way — and does not exist for the client we actually use every day.

## What to do

- Write the instruction file for Claude Code: when to call `memory_search` (before any
  task, to load prior context), when to call `memory_capture` (after research or an
  architectural decision, not for scratch), and when `memory_think` earns its cost.
- Make the capture rule discriminating. A memory that stores everything is noise; the
  boundary between a consequential decision and transient chatter is the whole design.
- Model it on `adapters/fabric/CLAUDE.md`, which already has the tool table and the
  before/after discipline. Reuse its shape rather than inventing a second dialect.
- Install it where it actually takes effect for daily work, and verify by observation:
  in a normal session, does the agent call the tools without being told in the prompt?
- Record the friction honestly — every point where the loop felt like overhead is input
  to the week-one verdict, not a detail to smooth over in the write-up.

## TDD Anchor

Behavioural, not unit-testable: in a session where the prompt says nothing about
memory, `memory_search` is called before the work and `memory_capture` after it.

## Acceptance Criteria

- [ ] An instruction file exists for the client used daily
- [ ] It states when to capture and, explicitly, when not to
- [ ] In a session with no memory instruction in the prompt, the agent searches first
      and captures after
- [ ] Observed friction is written down rather than smoothed over
