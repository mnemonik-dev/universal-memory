# Task 7: Minimal continuous integration

## Description

There is no `.github/workflows/` directory; nothing runs on push or on a pull request,
and PR #1 was merged with zero checks. This task adds only what protects daily use —
the suite and the end-to-end smoke test — and nothing more. It is deliberately in the
last wave: infrastructure protects something that exists, and until wave 2 nothing is
being used.

## What to do

- Create `.github/workflows/ci.yml` on push to `main` and on every pull request.
- Steps: checkout with `submodules: recursive` (the build cannot work without
  `vendors/gbrain` — decisions F1), pin Bun, `bun install` in `vendors/gbrain` then in
  `packages/memory-hub`, `bun run test` (never a bare `bun test` — the real timeout
  lives in the script), then `bun run scripts/mcp-smoke.ts`.
- The smoke test gates. Mocked units once stayed green while the product threw on the
  first real capture (decisions F2); the suite alone is not a sufficient signal.
- Add a gitleaks job over the working tree and history, matching sibling repositories.
- Fail with a named error if the submodule checkout leaves `vendors/gbrain` empty — a
  dead pin should be legible, not a downstream module-resolution mystery.
- Resist scope: no benchmark job, no deployment job, no matrix. Those come back when
  something needs them.

## TDD Anchor

Not applicable — configuration. Verification is the run on a real pull request.

## Acceptance Criteria

- [ ] `.github/workflows/ci.yml` runs on push to `main` and on pull requests
- [ ] The suite job is red when a test fails (verify on a scratch branch, then revert)
- [ ] The smoke job is red on a non-zero exit from `scripts/mcp-smoke.ts`
- [ ] gitleaks runs over working tree and history
- [ ] An empty `vendors/gbrain` fails with a message naming the submodule
- [ ] No job beyond suite, smoke and secret scan
