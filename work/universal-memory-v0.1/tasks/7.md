# Task 7: Live Mnemonik signing round trip

## Description

Verifiable provenance is the project's differentiator — Ed25519 signatures, COSE_Sign1
artifacts, Arweave storage, Solana anchoring — and it has never run. Every test log
carries `MNEMONIC_JWT not set` and `MNEMONIC_IDENTITY not set`; `memory_sign` and
`memory_verify` are covered only by mocked units. Prove the path works against the real
Mnemonik service once, and document it so the next person can repeat it.

## What to do

- Obtain credentials the documented way: `npx @mnemonik-xyz/cli login` for the JSON Web
  Token and `npx @mnemonik-xyz/cli init` for the identity keypair.
- Run the full round trip against a live server: capture a memory with
  `MNEMONIK_SIGNING=true`, confirm an attestation identifier is stored, then
  `memory_verify` it and confirm the signature validates.
- Do the same in both write modes the protocol offers — `local` (free, offline) and
  `participate` (anchored, paid) — or, if `participate` is not fundable now, record
  precisely what was and was not proven rather than implying both.
- Write the procedure into `docs/` as a runbook: prerequisites, commands, expected
  output, and how to tell a genuine verification from a degraded one.
- Never commit a token, an identity file or a key. Confirm gitleaks (task 1) covers the
  paths these land in, and that `.gitignore` excludes them.
- Per decision D6 this does not make signing mandatory; `MNEMONIK_SIGNING` stays off by
  default and the release does not gate on Mnemonik availability.

## TDD Anchor

- `sign_then_verify_round_trip_live` — gated on both credential variables; capture,
  sign, verify, assert a positive verification result.
- `verify_detects_tampered_content` — alter the stored content, assert verification
  fails. A verifier that never returns false has not been tested.
- `signing_disabled_without_credentials` — the existing warning path stays intact.

## Acceptance Criteria

- [ ] A live sign → verify round trip is completed and its output recorded
- [ ] Tampered content fails verification
- [ ] Which write modes were proven is stated exactly, with no implied coverage
- [ ] A runbook exists in `docs/` that a newcomer can follow
- [ ] No credential, token or key is committed; gitleaks covers their paths
- [ ] Default behaviour is unchanged when credentials are absent
