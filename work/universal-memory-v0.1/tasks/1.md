# Task 1: Continuous integration pipeline

## Description

The repository has no `.github/workflows/` directory at all. Nothing runs on push or
on a pull request — PR #1 was merged with zero checks. Create the pipeline that runs
the suite, the smoke test and a secret scan, so a regression is caught by a machine
rather than by someone running `bun test` by hand months later.

## What to do

- Create `.github/workflows/ci.yml`, triggered on push to `main` and on every pull
  request.
- Steps, in order: checkout with `submodules: recursive` (the build is impossible
  without `vendors/gbrain` — see decisions F1), set up Bun (pin the version, `>= 1.3.10`
  per README), `bun install` in `vendors/gbrain` then in `packages/memory-hub`,
  `bun run test` (never a bare `bun test` — see decision D2), then
  `bun run scripts/mcp-smoke.ts`.
- Add a gitleaks job scanning the working tree and full history, matching the sibling
  repositories' convention.
- The workflow must fail loudly if the submodule checkout produced an empty
  `vendors/gbrain` — a dead pin should surface as a named error, not as a confusing
  module-resolution failure downstream.

## TDD Anchor

Not applicable — this task produces workflow configuration. Verification is the run
itself, on a real pull request.

## Acceptance Criteria

- [ ] `.github/workflows/ci.yml` exists and triggers on push to `main` and on pull requests
- [ ] A pull request from this branch shows the checks running
- [ ] The suite job is red when a test fails (verify by pushing a deliberately broken
      test to a scratch branch, observing red, then reverting)
- [ ] The smoke job runs `scripts/mcp-smoke.ts` and is red on a non-zero exit
- [ ] gitleaks runs over working tree and history
- [ ] An empty or unfetchable `vendors/gbrain` fails with a message naming the submodule
