# Task 1: Deploy a persistent hosted instance

## Description

Everything else in this specification assumes one brain reachable from any machine.
`DEPLOY.md`, `docker-compose.yml`, `docker/memory-hub/Dockerfile` and
`nginx/memory.conf` all exist and have never been run against a real host. This task
makes the hub real, and corrects the runbook wherever following it proves it wrong.

## Target (approved 2026-09-06)

Hetzner Cloud, Ubuntu 22.04+. Sizing per `DEPLOY.md`: 4 vCPU / 8 GB / 40 GB minimum with
the Ollama service; 16 GB if `memory_think` synthesis is wanted. The deploy is executed
by the owner on the server — the specification session's sandbox has HTTPS-only egress
and cannot open SSH — and verified from outside over HTTPS by the agent.

## What to do

- Deploy per `DEPLOY.md`: Docker Compose, nginx reverse proxy, Let's Encrypt HTTPS,
  Postgres with pgvector, `MEMORY_API_KEY` for Bearer authentication.
- Fix `DEPLOY.md` as you go. An unfollowed runbook is a draft.
- Verify persistence deliberately: capture a memory, restart the whole stack, recall it.
  Postgres data must live on a named volume, not in the container layer.
- Verify the authentication boundary: a request without a token, and one with a wrong
  token, are both refused; `validateBearer` already uses a constant-time comparison.
- Confirm no secret reaches the logs — `config.ts` scrubs them, and that must hold in
  production, including the startup banner and any error path.
- This is the first time `CloudAdapter` meets a real Postgres. If it breaks, fix it
  here; it is a blocker for the whole specification, not a testing nicety.

## TDD Anchor

Not unit-testable — this is a deployment. Verification is external observation.

## Acceptance Criteria

- [ ] The instance answers a Model Context Protocol call over HTTPS from another machine
- [ ] Requests with no token and with a wrong token are refused
- [ ] A memory captured before a full stack restart is recallable after it
- [ ] No secret appears in any log, including startup and error paths
- [ ] `DEPLOY.md` was followed end to end and corrected where wrong
- [ ] The health endpoint the Dockerfile probes returns success
