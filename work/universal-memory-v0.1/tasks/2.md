# Task 2: TypeScript configuration + working typecheck

## Description

`packages/memory-hub/package.json` declares `"typecheck": "tsc --noEmit"`, but there is
no `tsconfig.json` in the package or anywhere in the repository. `tsc` therefore prints
its help text and exits 1 without compiling a single file — the script has never
checked anything. Give the package a real configuration and fix whatever type errors
that surfaces.

## What to do

- Add `packages/memory-hub/tsconfig.json`: ESNext modules, bundler resolution, strict
  mode on, `noEmit`, `types` including Bun's, `include` covering `src/` and `scripts/`.
- Run `bun run typecheck` and fix the errors it reveals. Expect the `any`-typed engine
  handles in `storage/local.ts` and `storage/cloud.ts` to be the noisy ones — type them
  where gbrain's exported types allow, and leave a narrow, commented `any` where they
  genuinely do not.
- Do not loosen `strict` to make errors disappear. If a rule is genuinely unworkable
  against gbrain's surface, disable that one rule with a comment naming the reason.

## TDD Anchor

- `bun run typecheck` exits 0 on the current tree.
- Introducing `const x: string = 42;` into any file under `src/` makes it exit non-zero
  naming that file — proving the script actually compiles the project.

## Acceptance Criteria

- [ ] `packages/memory-hub/tsconfig.json` exists with `strict: true`
- [ ] `bun run typecheck` exits 0 and reports no errors
- [ ] A deliberately introduced type error makes it exit non-zero, naming the file
- [ ] `bun run test` still passes 362/362
- [ ] No `strict` family flag was disabled wholesale to reach green
