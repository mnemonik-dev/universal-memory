# Task 8: One-command installation

## Description

The running server tells users to run `bunx universal-memory setup` — that string is
printed in the synthesis fallback — but nothing is published anywhere, so the command
fails for everyone. Installation today is: clone, `git submodule update --init`,
`bun install` in `vendors/gbrain`, `bun install` in `packages/memory-hub`. The blocker
is structural: `gbrain` is a `workspace:` dependency pointing at a git submodule, which
a registry publish cannot resolve.

## What to do

- Evaluate the three options named in decision D7 and pick one:
  (a) publish the gbrain fork to the registry and depend on the published version,
  (b) bundle a built gbrain into the published tarball,
  (c) ship a thin installer that fetches gbrain at install time.
  Deciding requires the built size and the gbrain licence — measure both, do not guess.
- Check the licence before anything else. If gbrain's terms do not permit republishing
  or bundling, options (a) and (b) are closed and the task says so instead of proceeding.
- Implement the chosen option so that a single documented command yields a working
  Model Context Protocol server on a machine that has never seen this repository.
- Make the printed hint honest: either `bunx universal-memory setup` works, or the
  string changes to whatever does.
- Record the choice, the measurements behind it, and the rejected options in
  `decisions.md`.
- If no option works without changing how gbrain is consumed, stop and report. Per the
  tech spec's risks, improvising a vendoring scheme mid-flight is not in scope.

## TDD Anchor

Not unit-testable — verification is an installation on a clean machine. The container
used for it must have no repository clone, no submodule, and no prior `bun install`.

## Acceptance Criteria

- [ ] The gbrain licence is checked and the finding recorded before implementation
- [ ] One documented command produces a working server on a clean machine
