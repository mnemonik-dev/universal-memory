# Task 4: Seed with real material + twenty-question recall check

## Description

Nothing real has ever been stored in this system. The only content that has passed
through it is three sentences the smoke test writes about PGLite and Reciprocal Rank
Fusion. Fill the brain with material we already have, then measure whether it gives the
material back — on questions we know the answers to, so the score means something.

## What to do

- Ingest our own corpus through the deployed instance: `work/` specifications and
  decision logs, `docs/architecture.md`, `docs/HANDOFF-adapter-integration.md`, the
  Fabric patterns, and session transcripts if they exist as files.
- Write twenty questions whose answers you already know from that material, spanning
  three kinds: a specific fact ("why was the gbrain submodule re-pinned"), a synthesis
  across documents ("what did we decide about egress and why"), and a negative ("what
  does the sync tool not do") — a memory that cannot say "I don't know" is not useful.
- Score honestly: correct, partially correct, wrong, not found. Publish the number as it
  comes out, including if it is bad.
- Record which mode produced the score — hosted, self-hosted embeddings, which model —
  so a later run is comparable.
- Note retrieval failures with enough detail to act on: was it chunking, ranking,
  ingestion, or a question the corpus genuinely cannot answer?

## TDD Anchor

- The twenty questions and their scores live in the repository as a file, not in a chat.
- Re-running the same questions after a re-ingest produces a comparable score.

## Acceptance Criteria

- [ ] Our real corpus is ingested into the hosted instance
- [ ] Twenty known-answer questions exist in the repository, covering fact, synthesis
      and negative cases
- [ ] Each is scored correct / partial / wrong / not found, with the total published
- [ ] The configuration that produced the score is recorded
- [ ] Failures are categorised by cause, not just counted
