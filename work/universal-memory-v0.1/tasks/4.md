# Task 4: First RUMBA benchmark run + published numbers

## Description

`README.md` claims the project is benchmark-driven and `docs/architecture.md` makes it
design principle 5, yet not a single measurement exists. Run the harness for the first
time and publish what it says — including if it says something unflattering.

## What to do

- Run `packages/eval/run.py` against the local backend with an embeddings provider
  configured. Record which provider and model were used; a BM25-only run measures a
  different system and must be labelled as such if it is the only one possible.
- Capture RecallAccuracy@5 and AnswerQuality, plus the mem0 baseline the harness
  compares against.
- Commit the result file with the date, the repository commit, the backend mode, the
  embedding provider and the RUMBA dataset revision. A number without those five facts
  is not reproducible.
- Put the headline numbers in `README.md`, next to the existing unmeasured gbrain
  claims ("P@5 49.1%, R@5 97.9%") — and mark clearly which numbers are gbrain's own and
  which are ours, measured here.
- If the harness assertion fails (`RecallAccuracy@5 >= mem0_baseline` or
  `AnswerQuality >= 0.7`), report the number honestly and open a follow-up; per decision
  D5 this does not block the release.

## TDD Anchor

- `run.py` exits 0 or 1 with an interpretable report — a crash or a silent exit is a
  task failure regardless of the scores.
- Re-running against the same dataset and commit reproduces the same figures within
  the harness's own tolerance.

## Acceptance Criteria

- [ ] A results file is committed containing date, commit, backend mode, embedding
      provider and dataset revision
- [ ] RecallAccuracy@5 and AnswerQuality are reported, alongside the mem0 baseline
- [ ] `README.md` carries the headline numbers, with our measurements distinguished
      from gbrain's published ones
- [ ] If a threshold failed, that is stated plainly rather than omitted
- [ ] The run is reproducible from the documented command
