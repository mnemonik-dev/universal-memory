# Task 4: Write path, bridged search, RRF fusion

## Description

Tag writes with their embedder, project them, and add the bridged candidate
generator to search. Same-embedder rows keep using gbrain's native path unchanged.

## What to do

1. `packages/memory-hub/src/config.ts` — return the resolved `embedding_model`
   from `initConfig()` (today it is only written to stderr) and expose
   `getEmbedModel(): string`. This is the only change to `config.ts`.
2. `packages/memory-hub/src/ingest/pipeline.ts` — after gbrain stores a memory,
   read back its raw vector, `project()` it, and `upsertRelative()`. Projection
   failure must not fail the write: log to stderr, leave the row unbridged, and
   let backfill (Task 5) pick it up. A memory that exists but is not bridged is
   recoverable; a lost memory is not.
3. `packages/memory-hub/src/storage/{local,cloud}.ts` — in `search()`:
   - native candidates from gbrain, as today, unchanged;
   - bridged candidates: embed the query once (already done by gbrain — reuse that
     vector, do not embed twice), project, `topK` over
     `listRelative({excludeEmbedModel: current})`;
   - fuse with RRF, `score = Σ 1/(k + rank_i)`, `k = 60`, both lists weighted equally
     for V1. Return `topK` of the fusion.
   - Each result carries `embedModel` and `viaBridge: boolean`.
4. `packages/memory-hub/src/mcp/server.ts` — surface `embed_model`,
   `anchor_set_id` and `via_bridge` on recall results so a client can tell a
   bridged hit from a native one.
5. Feature flag `UM_BRIDGE=off|on` (default `on` once Task 6 is green; `off` until
   then). `off` must restore byte-identical pre-bridge behaviour.

## TDD anchors

- Write under mock embedder A, search under mock embedder B: bridged results are
  returned, correctly ordered, and flagged `viaBridge: true`.
- Same-embedder search returns the identical ranking as before the change
  (regression guard — the bridge is additive).
- `UM_BRIDGE=off` produces no relative writes and no bridged reads.
- Query text is embedded exactly once per search (assert on call count).
- An upsert failure during ingest does not fail the memory write.

## Done when

Integration tests green, `UM_BRIDGE=off` regression test green, and no call-count
increase in embedder usage for same-embedder search.
