# Task 2: Projector and anchor-matrix cache

## Description

Implement the projection `r(x) = normalize(M_E · normalize(v))` and the cache that
keeps `M_E` from being recomputed.

## What to do

1. `src/project.ts`:
   - `buildAnchorMatrix(embed: (texts: string[]) => Promise<Float32Array[]>, set: AnchorSet): Promise<AnchorMatrix>`
     — embeds all anchors (batched, ≤ 64 per call, bounded concurrency), L2-normalizes
     each row, returns `{ anchorSetId, embedModel, dim, rows: Float32Array }` as one
     flat `N*d` buffer.
   - `project(v: Float32Array, M: AnchorMatrix): Float32Array` — L2-normalize `v`,
     single mat-vec over the flat buffer, L2-normalize the result. No allocation
     inside the inner loop.
   - `projectBatch(vs, M)` for backfill throughput.
2. `src/cache.ts` — persist matrices at
   `${dataDir}/embedding-bridge/${anchorSetId}/${slug(embedModel)}.f32`
   with a small JSON header (`{anchorSetId, embedModel, dim, n, createdAt}`).
   Load-or-build on first use; validate header against the requested set and
   refuse to use a mismatched cache rather than silently rebuilding.
3. `src/search.ts` — `topK(queryRel, rows, k)`, cosine over unit vectors
   (i.e. dot product), returning `{memoryId, score}[]`.

## TDD anchors

- Against a 3-anchor hand-computed matrix, `project` matches expected values to 1e-6.
- `project(v)` and `project(2v)` are identical (scale invariance).
- A zero vector does not produce `NaN` — it returns a zero relative vector and the
  caller treats it as unsearchable.
- Cache round-trip preserves values bit-exactly; a header with the wrong
  `anchorSetId` throws rather than rebuilding in place.
- `topK` ties break deterministically by memory id.

## Done when

Unit tests green; building a matrix for a mock 8-dim embedder over 1024 anchors
completes and caches, and a second call does not re-embed (assert on call count).
