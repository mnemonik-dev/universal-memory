# Task 8: Audit wave — read-only

# Description

Read-only audit of the whole branch. Writes findings to `decisions.md`; changes no
code. Fixes are filed as follow-up tasks.

## Security review

1. **D5 enforcement — the main item.** Prove on the diff that relative vectors are
   never logged, never exported, and never anchored. Grep the write paths, the MCP
   response shapes, every stderr write, and the Mnemonik attestation payloads.
   Relative vectors carry the same sensitivity as raw embeddings: embedding
   inversion and unsupervised cross-space translation are demonstrated in
   [arXiv:2505.12540](https://arxiv.org/abs/2505.12540).
2. **Tenant isolation.** Every `listRelative` / `topK` path is scoped by `user_id`.
   A missing `user_id` must narrow to nothing, never widen to everything.
3. **Anchor-set substitution.** What happens if an attacker swaps the corpus file?
   Task 7's verification must be on the read path, not only in tests.
4. **Untrusted input.** `anchor_set_id` and `embed_model` arriving from a client
   are parameters to parameterized queries only — assert no string interpolation.
5. **Resource bounds.** Anchor-matrix build over 1024 texts against a slow provider
   must be bounded and cancellable; a bridged scan must have a row cap.
6. Run the repo's gitleaks hook over the branch.

## Code review

1. No import from `vendors/` in bridge code (Decision D2).
2. No re-embedding of the same text within one request path.
3. float32 ↔ `BYTEA` codec: endianness explicit, length validated on read.
4. Numerical edge cases: zero vectors, non-finite values, dimension mismatch —
   each has a defined behaviour and a test, not an implicit `NaN`.
5. Every file added stays under ~150 lines, per repo convention.

## Done when

Findings are appended to `decisions.md` as a dated entry with severity per item,
and each critical/high finding has a follow-up task file. Zero findings is a valid
result only if the checklist above was actually walked item by item.
