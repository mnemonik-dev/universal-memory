# Task 1: Anchor set and content-addressed identity

## Description

Create `packages/embedding-bridge` and the frozen anchor corpus that every
relative representation is computed against.

## What to do

1. Scaffold `packages/embedding-bridge` as `@universal-memory/embedding-bridge`
   (ESM, TypeScript, `bun test`, matching `packages/memory-hub/package.json` shape).
2. Build `src/anchors/anchor-set-v1.json`: 1024 short passages (1–3 sentences),
   spread across technical prose, narrative prose, source code, dialogue,
   numeric/tabular text, and non-English text. Deduplicate exactly and
   near-duplicate by trigram Jaccard > 0.8. **No user data, no ingested memories** —
   the corpus ships in the repo and is public by construction.
3. `src/anchors.ts` exposes:
   - `loadAnchorSet(id?: string): AnchorSet` — `{ id, version, anchors: string[] }`.
   - `computeAnchorSetId(anchors: string[]): string` —
     `blake3(canonical_cbor(["um-anchors-v1", anchors]))`, hex. Order-sensitive.
   - `assertAnchorSetIntegrity(set)` — recompute and compare, throw on mismatch.
4. Reuse the canonical-CBOR encoder from `@mnemonik-xyz/sdk` if it exports one;
   otherwise implement deterministic CBOR for the `[string, string[]]` shape only
   (~40 lines) and note the choice in `decisions.md`.

## TDD anchors

- `computeAnchorSetId` is stable across runs and processes.
- Swapping two anchors changes the id.
- The id recorded in `anchor-set-v1.json` matches a fresh recomputation (this test
  is the guard against silent corpus edits).
- The corpus has exactly 1024 entries, no exact duplicates, no empty strings.

## Done when

`bun test packages/embedding-bridge/src/anchors.test.ts` is green and the anchor
set id is written into the JSON file itself.
