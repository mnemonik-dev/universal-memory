# Task 5: Backfill CLI for existing databases

## Description

Project the relative vectors for memories written before the bridge existed. No
text is re-embedded — the stored raw vector is sufficient.

## What to do

1. `packages/embedding-bridge/bin/backfill.ts`, runnable as
   `bun run backfill --data-dir … [--user …] [--batch 512] [--dry-run]`.
2. For each distinct `embed_model` present in the memory store, load or build that
   model's anchor matrix, then `projectBatch()` and `upsertRelative()` in batches.
3. **The hard constraint:** building `M_E` for an old model requires that provider
   to be reachable now. If a database holds rows written under
   `openai:text-embedding-3-small` and no `OPENAI_API_KEY` is configured today,
   those rows cannot be bridged. Handle it explicitly:
   - report per-model coverage before doing any work;
   - name the unreachable models and the env var each one needs;
   - backfill everything reachable and exit non-zero with the remaining count —
     never exit 0 on a partial backfill.
4. Mitigation for future writes: build and cache the active model's anchor matrix
   eagerly at first ingest, so the matrix survives the key being removed later.
   This is the reason `src/cache.ts` persists to disk.
5. Idempotent and resumable: re-running skips `(memory_id, anchor_set_id)` pairs
   that already exist unless `--force`.

## TDD anchors

- Backfilling a seeded 500-row store bridges every row; a second run does no writes.
- A store with two `embed_model` values, one unreachable, exits non-zero, bridges
  the reachable model fully, and names the missing env var.
- `--dry-run` performs no writes and reports the same counts the real run produces.
- Interrupting mid-batch and re-running leaves no partial or duplicate rows.

## Done when

Backfill of a seeded multi-model store is green, and the partial-coverage path is
covered by a test rather than by documentation.
