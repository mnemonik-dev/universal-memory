# User Spec: Embedding Bridge — кросс-эмбеддерная память через anchor-relative представления

## Проблема

`packages/memory-hub/src/config.ts` выбирает эмбеддер по тому, какой API-ключ найден
в окружении, в порядке приоритета:

| Условие | `embedding_model` | Размерность |
| --- | --- | --- |
| `OPENAI_API_KEY` | `openai:text-embedding-3-small` | 1536 |
| `GOOGLE_API_KEY` | `google:text-embedding-004` | 768 |
| Ollama доступен | `ollama:nomic-embed-text` | 768 |

Из этого следует, что **память, записанная на одном провайдере, не ищется на другом**:

1. **Громкий отказ.** OpenAI (1536) → Google (768): несовпадение размерности,
   векторный поиск падает или отдаёт ноль результатов.
2. **Тихий отказ — хуже.** Google (768) → Ollama `nomic-embed-text` (768):
   размерность совпадает, но геометрия пространств разная. Косинус считается,
   результаты возвращаются, и они бессмысленные. Пользователь этого не видит.

Universal Memory обещает «единый слой памяти, работающий с любого клиента»
(`README.md`). Сегодня это обещание держится только пока пользователь не меняет
провайдера, не переезжает с ноутбука (Ollama) на сервер (OpenAI), не делится
памятью с другим человеком и не остаётся без интернета. Mnemonik-подпись при этом
работает как задумано — она удостоверяет байты, — но *найти* подписанную память
чужим эмбеддером нельзя. Provenance есть, портируемости нет.

## Что делаем

Добавляем **мост между пространствами эмбеддингов** — не переэмбеддинг, не
привязку к одному провайдеру, а инвариантное представление поверх любого
эмбеддера.

Механика (Moschella et al., ICLR 2023, «Relative representations enable zero-shot
latent space communication», arXiv:2209.15430): фиксируем набор из N якорных
текстов (anchors). Любой эмбеддер E кодирует эти якоря один раз. Тогда для памяти
`x` вместо абсолютного вектора `E(x)` мы храним вектор косинусных близостей к
якорям:

```
r(x) = [ cos(E(x), E(a_1)), ..., cos(E(x), E(a_N)) ]  ∈  R^N
```

`r(x)` имеет размерность N независимо от провайдера, и — при достаточно
разнообразном наборе якорей — приблизительно совпадает у разных эмбеддеров для
одного и того же текста. Поиск идёт косинусом по `r(x)`. Обучать нечего:
это чистая арифметика поверх уже посчитанных векторов.

Что получает пользователь:

1. **Переносимость.** Память, записанная на ноутбуке через Ollama, ищется в облаке
   через OpenAI. Смена провайдера перестаёт быть разрушающей операцией.
2. **Отсутствие тихой порчи.** Каждая строка помечается `embed_model`; поиск между
   разными моделями идёт только через мост, никогда — «сырым» косинусом.
3. **Проверяемый общий базис.** Набор якорей — сам по себе артефакт: канонический
   CBOR, blake3-хеш, COSE_Sign1-подпись через Mnemonik. Два клиента могут
   *доказать*, что считали относительные представления в одном базисе, а не
   надеяться на это. Этого нет ни у кого из конкурентов по памяти.
4. **Отсутствие вендор-лока.** Пользователь без ключей (Ollama-режим) работает в
   том же пространстве поиска, что и пользователь с OpenAI.

## Чего НЕ делаем

- **Не трогаем `vendors/gbrain`** — это сторонний submodule (`garrytan/gbrain`).
  Мост живёт слоем выше, в отдельном пакете плюс sidecar-таблица в `memory-hub`.
- **Не заменяем нативный поиск.** Когда `embed_model` строки совпадает с текущим,
  работает существующий путь gbrain. Мост — второй кандидат-генератор, результаты
  сливаются через RRF (Reciprocal Rank Fusion), уже используемый в hub.
- **Не переэмбеддим.** Пересчёт `r(x)` требует сохранённого сырого вектора и
  якорной матрицы того же эмбеддера — исходный текст заново кодировать не нужно.
- **Не обещаем приватности.** Относительное представление — не анонимизация.
  См. `decisions.md`, решение D5.
- **Не про латентные состояния моделей.** Это мост между *эмбеддингами*, а не
  между hidden states LLM. Латентный мост — отдельное исследование,
  `research/latent-bridge/`.

## Критерий приёмки (kill-critical)

Фича живёт только если измерена на RUMBA (`research/RUMBA`):

> Кросс-эмбеддерный Recall@10 через мост ≥ **85 %** от одноэмбеддерного
> Recall@10 на той же выборке, для всех трёх пар из матрицы
> {openai, google, ollama}.

Если порог не берётся ни на одном разумном размере набора якорей (N ≤ 2048) —
фича закрывается, результат фиксируется в `decisions.md`, код не мержится.
Это не формальность: гипотеза может не подтвердиться на этих конкретных моделях.
